# 予想投資ワークフロー連携機能 要件書

## 概要

現在実装されている競馬予想機能、投資記録機能、統計分析機能を統合し、レース予想→馬券購入記録→レース結果入力→統計分析という一連のワークフローを効率的に実行できる機能を実装する。これにより、予想の精度向上と投資パフォーマンスの最適化を図る。

## 要件

### 要件1: 予想から投資記録への連携

**ユーザーストーリー:** 予想者として、作成した予想結果から直接馬券購入記録を作成したい。これにより、予想と実際の投資を紐付けて管理できる。

#### 受入基準

1. WHEN 予想結果画面で「投資記録」ボタンをクリック THEN 予想データが事前入力された投資記録フォームが表示される
2. WHEN 投資記録フォームで予想データが事前入力されている THEN レース情報（競馬場、レース番号、日付）、予想ID、レースIDが自動設定される
3. WHEN 投資記録フォームで券種を選択 THEN 予想結果の上位馬が買い目候補として表示される
4. WHEN 単勝・複勝を選択 THEN 1位予想馬が自動選択される
5. WHEN 馬連・馬単を選択 THEN 1位・2位予想馬が自動選択される
6. WHEN 3連複・3連単を選択 THEN 1位・2位・3位予想馬が自動選択される
7. WHEN 投資記録を保存 THEN 予想IDと投資記録IDが相互に関連付けられる

### 要件2: レース結果入力機能の強化

**ユーザーストーリー:** 予想者として、予想したレースの結果を効率的に入力したい。これにより、予想精度を正確に記録し、関連する投資記録がある場合は自動的に損益を計算できる。

#### 受入基準

1. WHEN 予想一覧で「結果入力」ボタンをクリック THEN 対応するレースの結果入力フォームが表示される
2. WHEN 結果入力フォームが表示される THEN 予想した馬の順位予想が表示される
3. WHEN レース結果（着順）を入力 THEN 予想精度（1着的中、3着以内的中等）が自動計算される
4. WHEN 関連する投資記録がある場合 THEN 投資記録の払戻額・損益が自動計算される
5. WHEN 投資記録がない場合 THEN 予想結果のみが更新される
6. WHEN 結果を保存 THEN 予想結果が更新され、統計データに反映される

### 要件3: 統合された統計分析

**ユーザーストーリー:** 分析者として、予想精度と投資パフォーマンスを統合して分析したい。これにより、予想手法と投資戦略の両方を改善できる。

#### 受入基準

1. WHEN 統計画面で「予想投資分析」タブを選択 THEN 予想精度と投資成績の相関分析が表示される
2. WHEN 予想精度別の投資成績を表示 THEN 確信度レベル別の回収率が表示される
3. WHEN 券種別の予想精度を表示 THEN 各券種での的中率と回収率が表示される
4. WHEN 期間別の統合分析を表示 THEN 予想精度の推移と投資成績の推移が同一グラフで表示される
5. WHEN 改善提案を表示 THEN 予想精度向上と投資戦略最適化の具体的な提案が表示される

### 要件4: ワークフロー状態管理

**ユーザーストーリー:** ユーザーとして、各レースの予想→結果入力、および投資記録→結果入力の進捗状況を把握したい。これにより、未完了のタスクを効率的に処理できる。

#### 受入基準

1. WHEN ホーム画面を表示 THEN 未完了のワークフロー（結果未入力の予想・投資記録等）が通知される
2. WHEN 予想一覧を表示 THEN 各予想の状態（投資記録有無、結果入力有無）がアイコンで表示される
3. WHEN 投資記録一覧を表示 THEN 各投資の状態（結果入力有無、払戻確定有無）がアイコンで表示される
4. WHEN 未完了タスクをクリック THEN 該当する入力画面に直接遷移する
5. WHEN 予想の結果入力が完了 THEN 完了マークが表示される
6. WHEN 投資記録の結果入力が完了 THEN 損益が確定し完了マークが表示される

### 要件5: データ整合性の保証

**ユーザーストーリー:** システム管理者として、予想データ、投資記録、結果データの整合性が保たれることを確認したい。これにより、正確な分析結果を提供できる。

#### 受入基準

1. WHEN 予想を削除 THEN 関連する投資記録の予想IDがnullに更新される
2. WHEN 投資記録を削除 THEN 関連する予想の投資記録参照が削除される
3. WHEN レース結果を更新 THEN 関連する全ての投資記録の損益が再計算される
4. WHEN データ不整合を検出 THEN エラーメッセージが表示され、修復オプションが提供される
5. WHEN データ同期を実行 THEN 全ての関連データの整合性がチェックされる

### 要件6: 投資記録の柔軟な管理

**ユーザーストーリー:** ユーザーとして、予想に対して投資記録を作成するかどうかを柔軟に選択したい。これにより、実際に馬券を購入した場合のみ投資記録を管理できる。

#### 受入基準

1. WHEN 予想を作成 THEN 投資記録の作成は任意である
2. WHEN 投資記録なしで結果入力 THEN 予想精度のみが記録される
3. WHEN 投資記録ありで結果入力 THEN 予想精度と投資成績の両方が記録される
4. WHEN 後から投資記録を追加 THEN 既存の予想結果と関連付けられる
5. WHEN 投資記録を削除 THEN 予想結果は保持される

### 要件7: 通知とリマインダー

**ユーザーストーリー:** ユーザーとして、重要なワークフローステップを忘れないよう通知を受けたい。これにより、データ入力漏れを防げる。

#### 受入基準

1. WHEN レース開始時刻が近づく THEN 投資記録未作成の予想について通知される
2. WHEN レース終了後 THEN 結果未入力の投資記録について通知される
3. WHEN 1日経過後 THEN 未完了のワークフローについてリマインダーが表示される
4. WHEN 通知をタップ THEN 該当するワークフローステップに直接遷移する
5. WHEN 通知設定で無効化 THEN 該当する通知が停止される

### 要件8: バックアップと復元

**ユーザーストーリー:** データ管理者として、ワークフロー関連データを安全にバックアップ・復元したい。これにより、データ損失を防げる。

#### 受入基準

1. WHEN データエクスポートを実行 THEN 予想、投資記録、結果データが関連付けを保持してエクスポートされる
2. WHEN データインポートを実行 THEN 関連付けが正しく復元される
3. WHEN 部分的なデータ復元を実行 THEN データ整合性チェックが実行される
4. WHEN バックアップデータに不整合がある THEN 修復オプションが提供される
5. WHEN 自動バックアップが有効 THEN 定期的にワークフローデータがバックアップされる
